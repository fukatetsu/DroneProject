# 顔追跡・人物追従機能 設計

## 1. 目的と位置づけ

カメラ画像から顔を検出・追跡し、選択した人物が画面中央に映るようにドローンの向きと高度を調整する機能の設計を定める。

本書は既存コードを調査したうえで、実装済みの機能と今後追加する機能を分けて記述する。顔検出・顔追跡・人物追従は現時点では未実装である。

## 2. 既存コードの確認結果

| 既存要素 | 実装と責務 | 顔追跡での利用 |
|---|---|---|
| `DroneController` | ドローン制御、状態取得、映像ストリームの抽象インターフェース | フレーム取得とRC制御の共通窓口 |
| `TelloController` | Tello映像をバックグラウンドで取得し、最新フレームを保持 | 実機映像の供給元 |
| `MockDroneController` | PCカメラを使った映像取得とドローン動作のモック | PC上での開発・統合テスト |
| `CameraViewer` | `DroneController.get_video_frame()`からフレームを取得 | 表示用。画像解析の責務は持たせない |
| `MediaController` | `CameraViewer`の起動、表示ループ、画面出力を管理 | 任意のデバッグ表示に利用 |
| `Show` | `start() / run() / stop()`の演出ライフサイクルと`DroneController`を提供 | 追従制御の実行場所 |
| `ScenarioRunner` | Showの生成・実行・終了、Pause/Land/Emergency等の操作を管理 | 既存のオペレータ介入を維持 |
| `ShowRegistry`・`main.py` | Show名の登録とシナリオからの生成 | 新しいShowと解析器の依存を注入 |
| `DroneState` | 高度、速度、yaw等のドローン状態を保持 | 高度制限・飛行状態の参照候補 |

`TelloController.get_video_frame()`は最新フレームを非ブロッキングで返し、OpenCVが利用可能な場合はBGRからRGBへ変換する。ただし、現行APIはフレームの取得時刻や連番を返さないため、古いフレームを確実に判定するにはフレームメタデータの追加が必要である。画像取得と表示は既に分離されているため、顔解析を`CameraViewer`や`MediaController`へ追加しない。

既存の`Analyzer`基底クラスは`ImuState`から`HoopState`を作るための型に結び付いている。顔解析器はこの基底クラスを無理に継承せず、顔画像用の状態型とAPIを定義する。

## 3. 設計方針

1. **既存の境界を維持する。** 顔画像の認識は解析器、飛行演出はShow、ドローン命令は`DroneController`が担当する。
2. **カメラ取得元を共用する。** `DroneController`が保持する同一の最新フレームを顔解析と任意のプレビューで利用する。解析用に別のカメラや別の取得ループを起動しない。
3. **追跡IDは一時的なトラックIDとする。** 顔の外見から個人を認証するものではない。検出が途切れたり、遮蔽・交差した場合はIDが変わり得る。
4. **フレーム欠落を即座に離着陸へ結び付けない。** 一時的な未検出、古いフレーム、処理停止を区別して段階的に扱う。
5. **人の顔サイズだけで実距離を断定しない。** 顔領域の大きさは撮影条件に依存する相対的な近さの推定値として扱う。
6. **操作者のPause、Land、Emergencyを優先する。** 自動制御中も既存の`ScenarioRunner`による介入を妨げない。

## 4. 推奨する構成

```text
DroneController.get_video_frame()
              │
              ├──> CameraViewer ──> MediaController（任意表示）
              │
              └──> FaceAnalyzer
                    └──> FaceTrackingState
                          └──> FaceFollowShow
                                └──> DroneController.send_rc_control()
```

実装時に追加・変更する候補は次のとおり。

| パス | 状態 | 責務 |
|---|---|---|
| `src/models/face_state.py` | 新規 | 顔検出結果と追跡状態の不変データモデル |
| `src/analyzers/face_tracking_analyzer.py` | 新規 | フレームから顔を検出し、フレーム間でトラックIDを関連付ける |
| `src/shows/interaction/face_follow_show.py` | 新規 | 候補選択、対象切替、追従用RC制御、安全な停止 |
| `src/main.py` | 変更候補 | 解析器を生成し、Showのファクトリへ注入 |
| `src/registry/show_registry.py` | 原則変更なし | 既存のファクトリ機構を利用 |
| `src/scenarios/` | 新規JSON候補 | 追従Showを起動するシナリオを定義 |

`src/inputs/imu/`はIMU入力専用の既存構成である。ドローン映像は既存の`DroneController`が供給するため、映像を重複取得する入力クラスは追加しない。将来、複数のカメラ入力方式が必要になった場合に、共通の映像入力インターフェースを設ける。

## 5. データモデル案

### FaceDetection

1人分の検出結果を表す。座標は同一フレーム内のピクセル単位とする。

| フィールド | 型の案 | 意味 |
|---|---|---|
| `track_id` | `int` | 解析器が割り当てた一時的な追跡ID |
| `x`, `y` | `int` | 顔矩形の左上座標 |
| `width`, `height` | `int` | 顔矩形の幅と高さ |
| `confidence` | `float` | 検出器が信頼度を返す場合の値 |

矩形から中心座標と面積を算出する。面積は近さ候補の順位付けにのみ使い、実距離とはみなさない。

### FaceTrackingState

1フレーム分の解析状態を表す。

| フィールド | 意味 |
|---|---|
| `detections` | そのフレームで検出した顔の一覧 |
| `frame_width`, `frame_height` | 正規化座標の計算に使う画像寸法 |
| `captured_at` | フレームの取得時刻。古いフレームの判定に使う |

未検出は空の`detections`として表す。フレームそのものを取得できない状態とは区別する。

## 6. 解析と追跡

`FaceAnalyzer`相当のコンポーネントは、1フレームを受け取り、顔検出とフレーム間の対応付けを行い、`FaceTrackingState`を返す。飛行命令、離着陸、対象選択は行わない。

処理の流れ:

1. `drone.get_video_frame()`で最新フレームを取得する。
2. フレームが`None`、または取得時刻が許容時間を超えて古い場合は、検出結果を新規フレームとして扱わず、映像入力異常を記録する。
3. 画像形式を検出器の入力形式へ明示的に変換する。現行Tello実装はRGBを返すため、BGRを前提とする検出器には解析境界で変換する。
4. 顔検出器を実行し、矩形と任意の信頼度を得る。
5. 前フレームの矩形との重なりや中心距離などで対応付けし、継続するトラックにはIDを維持する。一定フレーム以上見つからないIDは破棄する。
6. 顔が検出されない場合も、正常な解析結果として空の一覧を返す。

検出器、関連付け方式、検出頻度は既存依存と実機の性能を測って選定する。現行`requirements.txt`にはOpenCVとNumPyがあるが、顔検出・追跡専用ライブラリは定義されていない。追加依存を決める前に、必要精度と実機性能を評価する。

## 7. 追従対象の選択

1. 現在有効なトラックを、顔矩形の面積が大きい順に並べる。
2. 上位3トラックを追従候補とする。3人未満の場合は検出された候補をすべて使う。
3. 初回は候補からランダムに選択する。
4. 選択後はIDを保持し、約15秒経過した時点で候補から再選択する。候補が複数ある場合は、直前の対象を避ける。
5. 対象が一時的に検出されない場合は短い保持期間を設ける。保持期間を過ぎても復帰しない場合に、残る有効候補へ切り替える。
6. 候補が0人の間は対象なし状態を維持し、フレームごとの無作為切替を行わない。

矩形面積はカメラとの相対的な近さの代替指標であり、カメラ角度・姿勢・顔の向きによって順位が変わる。実距離が必要なら、距離センサー等の別情報を設計に加える。

## 8. 追従制御

`FaceFollowShow`は`Show`の`start() / run() / stop()`に従い、選択対象の顔中心と画像中心との差からRC指令を計算する。制御ループは既存のShowと同様に`asyncio`で周期実行し、周期は設定値として持つ。

正規化誤差の定義案:

```text
error_x = (face_center_x - frame_width / 2) / (frame_width / 2)
error_y = (face_center_y - frame_height / 2) / (frame_height / 2)
```

- 左右誤差はyaw軸、上下誤差は`up_down`軸に割り当てる。
- デッドバンドを設け、誤差が小さい間は該当軸を0にする。
- 比例ゲインとRC指令の最大値を設定可能にし、TelloのRC範囲内に制限する。
- 画面上下と上昇・下降、画面左右とyaw方向の符号は、実機で低速・低高度から確認して確定する。
- 顔矩形の大きさを使った前後移動は本設計の初期範囲に含めない。近さ推定の信頼性と衝突回避要件が定まってから別途設計する。
- 命令を送る頻度を抑え、フレーム更新が止まった場合には追従命令を継続しない。

`stop()`とキャンセル経路ではRC指令を全軸0にする。既存の`DroneController.send_rc_control()`は移動コマンドのロック中にRC指令を無視するため、追従ShowではRC制御を継続している間に`move_*`等のブロッキング移動命令を併用しない。

## 9. 状態遷移と安全動作

```text
停止中
  └─ Show.start() ─> 探索中
                       ├─ 有効な対象 ─> 追従中
                       ├─ 対象一時消失 ─> 対象喪失猶予中
                       │                    ├─ 対象復帰 ─> 追従中
                       │                    └─ 猶予超過 ─> 対象再選択 / 対象なし
                       └─ 映像入力異常 ─> RC停止・異常記録
```

| 状態・事象 | 動作 |
|---|---|
| 顔検出の短時間の失敗 | 直ちに対象を切り替えず、現在のトラックを保持 |
| 対象喪失猶予超過 | 残る候補へ切り替える。候補がなければRC全軸0 |
| フレーム取得不能・古いフレーム | 追従制御を止め、RC全軸0。復旧しない場合はShowを異常終了 |
| Pause | 既存`ScenarioRunner`の停止処理を優先 |
| Land / Emergency | 既存コールバックを優先し、Show側で競合する命令を発行しない |
| Show終了・例外・キャンセル | `stop()`でRC全軸0にし、起動した映像リソースを確実に解放 |

`DroneState.height_tof`を高度制限の監視に利用する場合も、センサー値の妥当性と制限値を実機で確認する。安全条件が確定するまで、高度に関する制御上限・下限は実装前の必須設定とする。

### 自動離陸・自動着陸について

元の要件には、人物の接近で離陸し、対象不在で着陸する案が含まれる。しかし現行コードにも顔の面積にも、実距離や離陸可否を安全に判定する仕組みはない。顔検出の有無だけで自動離陸すると、誤検出や通行人への反応が起こり得る。

したがって初期実装では、追従Showが自動離陸を行わない設計とする。離陸・着陸を自動化する場合は、操作者による明示的な開始条件、近接判定の校正、連続判定時間、離着陸のヒステリシス、緊急停止手順を別途定義し、実機試験で承認する。対象喪失時の基本動作は、まずRC全軸0とし、自動着陸はその安全条件が決まるまで行わない。

## 10. カメラストリームと表示の統合

現在は`CameraViewer.start()`が`DroneController.start_video_stream()`を呼び、停止時に`stop_video_stream()`を呼ぶ。一方、顔解析もフレームを必要とする。複数の利用者が個別に開始・停止すると、二重の`streamon()`、片方の停止による他方のフレーム喪失が起こり得る。

実装時は、映像ストリームの開始・停止を単一の所有者に集約する。顔解析と任意の`CameraViewer`は同じストリーム・同じ最新フレームを読むだけとし、どちらか一方が勝手に共有ストリームを停止しないようにする。これは統合時に必要な設計変更であり、現在の`CameraViewer`がその共有管理を実装済みという意味ではない。

## 11. Show・Scenarioへの統合

- `FaceFollowShow`は`Show`を継承し、ドローン命令を`DroneController`経由で送る。
- 顔解析器をShowの外部依存として注入する。既存の`register_builtin_shows()`は`requires_analyzer`の場合に`HoopAnalyzer`を渡す実装なので、顔解析器の注入方法を追加する際は、フラグと型が不一致にならないようファクトリを拡張する。
- `ShowRegistry`の名前登録と`ScenarioRunner`のライフサイクルを利用し、シナリオJSONから追従Showを起動する。
- `--camera`は現在MediaControllerの出力有効化用であり、追従機能の映像入力開始オプションとして扱わない。必要なら入力有効化と表示有効化を別の設定にする。
- `MockDroneController`のPCカメラとモック飛行制御で、検出・対象選択・状態遷移を実機接続なしで検証できるようにする。

## 12. テスト計画

1. **モデル:** 矩形の中心・面積、空の検出一覧、異なる画像サイズを検証する。
2. **解析器:** 検出結果、トラックIDの維持、遮蔽後のID再割当、フレームなし・古いフレームを検証する。
3. **対象選択:** 面積順の上位3名、候補が1〜2名の場合、15秒切替、同じ対象の連続選択回避、対象喪失猶予を検証する。
4. **制御:** 中心位置でゼロ指令、上下左右の符号、デッドバンド、上限値、フレーム異常時のRC停止を検証する。
5. **Showライフサイクル:** 開始・停止・例外・キャンセル時のRC停止とストリーム解放を検証する。
6. **統合:** MockカメラでShow登録、シナリオ起動、Pause/Land/Emergencyとの共存を検証する。
7. **実機:** 十分な空間と監視者のもと、低速・低高度・手動停止可能な状態から制御方向と高度制限を確認する。

## 13. 実装前に決定・校正する事項

- 顔検出器とトラッカーの方式、実機での処理速度
- 入力フレームの解像度、色順、許容されるフレーム鮮度
- 対象喪失の猶予時間とトラックIDの有効期間
- 約15秒の対象切替時に候補が1名しかいない場合の挙動
- 顔面積を近さの相対指標として使う際の閾値と誤差
- RC制御周期、デッドバンド、ゲイン、最大速度
- 高度の安全範囲と高度情報の採用可否
- 自動離陸・着陸を将来導入する場合の明示的な許可条件
- 映像ストリームの共通所有者とプレビュー表示との共有方法

これらの値を実機で検証し、決定後に設定値・テスト条件として固定する。未確定の値を暗黙の既定値として飛行制御に使わない。
